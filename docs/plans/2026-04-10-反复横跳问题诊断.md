# 反复横跳问题诊断报告

> 时间：2026-04-10 21:20
> 问题：用户报告"反复横跳到25秒"
> 方法：5个子agent并行审查

---

## 🔴 根本原因

**Hard Resync 时重置 `_anchorConsumedBase = 0` 导致 getCurrentTime() 返回错误值**

---

## 循环触发机制

```
┌────────────────────────────────────────────────────────────────┐
│ 1. 某次 drift > 500ms → Hard Resync                             │
│    _anchorConsumedBase = 0, SharedArrayBuffer = 0              │
│                                                                 │
│ 2. worklet 继续消耗帧 → consumed 增长（如 4096 帧）              │
│                                                                 │
│ 3. getCurrentTime() 计算                                        │
│    consumedDelta = 4096 - 0 = 4096                              │
│    pos = expectedPos + 4096/48000 = expectedPos + 0.085s        │
│    → 返回值比真实位置多 85ms！                                   │
│                                                                 │
│ 4. statusReport 发送错误位置（每 2 秒）                          │
│                                                                 │
│ 5. 服务器计算 drift                                             │
│    clientPos = expectedPos + 0.085s                             │
│    serverPos = expectedPos + elapsed                            │
│    drift = |clientPos - serverPos|                              │
│    如果 elapsed ≈ 2s, drift ≈ 2000ms                            │
│                                                                 │
│ 6. drift > 400ms → 再次 forceResync                             │
│                                                                 │
│ 7. 循环重复 → "反复横跳"                                        │
└────────────────────────────────────────────────────────────────┘
```

## 修复方案

**关键修复**：Hard Resync 时**不重置** `_anchorConsumedBase`，而是读取当前 consumed 值作为新基准

```javascript
// 之前（错误）
this._anchorConsumedBase = 0;
Atomics.store(this._sharedView, 0, 0n);
this.workletNode.port.postMessage({ type: 'clear' });

// 现在（正确）
let currentConsumed = Number(Atomics.load(this._sharedView, 0));
this._anchorConsumedBase = currentConsumed; // 使用当前值
// 不重置 SharedArrayBuffer
// 不发送 'clear' 消息
```

**原理**：
- consumedDelta = consumed - currentConsumed
- worklet 继续消耗帧时，consumed 增长
- currentConsumed 记录了基准点
- delta 只包含从 Hard Resync 后的增长部分（正确！）
